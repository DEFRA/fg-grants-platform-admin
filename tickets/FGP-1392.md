# FGP-1392: Event List View — merged GAS + Caseworking inbox/outbox events in Grants Platform Admin

**Story · Lowest · Donatas Bacius · Sprint 52 · Epic: Core Platform Support & Management (Dev Ops) · Clones FGP-1227**

## Narrative

As a Grant Operations Administrator (`FCP.GrantOperationsAdmin`)
I want a paginated table of every inbox and outbox event across GAS and Caseworking
So that I can see queued, retrying, completed and dead-lettered messages without database access.

## Context

The Grants Platform moves work between GAS and Caseworking through Mongo-backed `inbox`/`outbox` collections (identical models in both services: six statuses, immediate retry on a 250 ms poll, dead-letter at 5 attempts, never purged). Today the only way to see a stuck message is a direct Mongo query, which is restricted and risky.

`fg-grants-platform-admin` is the Grants FE; `fg-gas-backend` is its backend-for-frontend (`/grant-admin/*`, service-token auth). GAS aggregates its own events with Caseworking's, fetched from CW actuator endpoints (FGP-1227) over the already-configured but so far unused `CW_BACKEND_URL` / `CW_BACKEND_TOKEN`.

The list endpoint deals in **generic inbox/outbox data only**. Business identifiers from event payloads are deliberately not exposed here; they arrive with the Inspect story.

## Scope

- Copy `fg-cw-backend/src/common/paginate.js` into `fg-gas-backend/src/common/paginate.js` (+ tests) — GAS has no pagination helper.
- Migrations: `inbox { eventTime: -1, _id: -1 }`, `outbox { publicationDate: -1, _id: -1 }`.

*fg-grants-platform-admin* (on top of branch `FGP-1227-operations-daisyui`)
- `GET /dev-ops/events` in the daisyUI `dev-ops` app: route → use case → repository (`getFromGas`) → view model → `views/events.njk`, scoped to `FCP.GrantOperationsAdmin`.
- Table with responsive horizontal scrolling; Previous/Next links; empty, error and partial-source states.
- Link to the page from the `/dev-ops` index.

**Out** (separate stories)
- Actions column (Inspect, Retry), count cards, Purge Completed, Audit History.
- Filter **controls** (application dropdown, status tabs) — the endpoint and page accept `status`/`service` query params now so those controls are UI-only follow-ups; with none given the page shows All.

- The CW actuator endpoints (**FGP-1227, blocker**).

- Real SQS dead-letter queues — messages that fail to parse never reach Mongo and will not appear here.
- Total counts and page numbers.
- Stale-claim detection (deferred; the endpoint returns the data for it).

## Behaviour

### Request flow
1. Browser → `GET /dev-ops/events[?cursor=…&direction=forward|backward][&status=…][&service=…]`.
2. FE repository → `getFromGas('/grant-admin/events?…')` forwarding `cursor`, `direction`, `status`, `service` verbatim (bearer `GAS_SERVICE_TOKEN`).
3. GAS use case fans out **in parallel** to four sources, each with its own slice of the composite cursor:
   - GAS `inbox.repository.findPage()` and `outbox.repository.findPage()` via `paginate()` with `pageSize: 20` (`paginate` adds the `+1` look-ahead itself). Sort keys are per source: inbox `{ eventTime: -1, _id: -1 }` (`eventTime` is an ISO string), outbox `{ publicationDate: -1, _id: -1 }` (a `Date`) — `createdAt` is the *derived output name*, not a stored field.
   - CW `GET {CW_BACKEND_URL}/actuators/inbox?cursor=&direction=&pageSize=20[&status=]` and `/actuators/outbox…` (bearer `CW_BACKEND_TOKEN`), which return the same `{ data, pagination }` envelope.
4. Merge by `(createdAt desc, service, box, _id desc)`; take 20; `hasNextPage` = any source returned more; `hasPreviousPage` = any source reports one.
5. Response cursor is composite and opaque: `base64url(JSON({ v: 1, gasInbox: <slice>, gasOutbox: <slice>, cwInbox: <slice>, cwOutbox: <slice> }))` — each slice is that source's **own** `paginate` cursor (`{ eventTime, _id }` for an inbox, `{ publicationDate, _id }` for an outbox, encoded with that source's codecs) for the last row taken from it; a source contributing no rows to the page keeps its incoming slice. `direction=backward` mirrors this per source then reverses, exactly as `paginate.js` does.
6. Any single source failing → still `200` with the rows the other sources returned and `sourceErrors: [{ service, box, message }]` (CW: 3 s `wreck` timeout, 401, 5xx, connection refused; GAS: a Mongo read error), logged as a one-line message (never a response body). `CW_BACKEND_URL`/`CW_BACKEND_TOKEN` unset (true in every environment today) → both CW sources report `message: "not configured"`. Both GAS reads failing → `502`.

### Filtering
- **Default is All.** With no `status` and no `service`, every event is eligible: all six statuses, GAS and Caseworking, inbox and outbox, domain and audit kinds. Nothing is hidden by default.
- `status=<one of the six>` → applied identically to every source as part of the `paginate()` filter (and passed through to the CW actuator calls). The cursor format is unchanged — it is a keyset position, so it stays decodable under any filter; the FE preserves `status`/`service` on Previous/Next links so a page keeps the filter it was opened with.
- `service=gas|caseworking` → only that service's two sources are queried; the other's cursor slice is left empty.
- Filters combine with AND.

### Field derivation (GAS use case, one mapper shared by all four sources)
| Field | Inbox | Outbox |
|---|---|---|
| `createdAt` | `eventTime` (producer's CloudEvent `time`) → fallback `_id` timestamp | `publicationDate` (normalised to `Date`) → fallback `_id` timestamp |
| `eventId` | `messageId` | `event.id` → audit/legacy rows without one: `_id` |
| `type` (short) | `type` with `cloud.defra.<env>.<service>.` stripped | `event.type` stripped; **audit rows** (recognised structurally: `event.audit.entities` present — audit payloads have no `event.id`/`event.type`): `audit · <entities[0].entity>.<entities[0].action>`; `io.onsite.*` legacy shown as-is; nothing derivable → `-` |
| `fullType` | raw `type` | raw `event.type`; `null` for audit rows |
| `source` | `source` (`GAS`/`CW`/`AS`) | `null` |
| `target` | `null` | `target` — SNS ARN reduced to topic name (`arn:…:cw__sns__x` → `cw__sns__x`), or `internal:message-bus` → `internal` |
| `segregationRef` | as stored | as stored |
| `status` | raw | raw |
| `attempts` / `maxAttempts` | `completionAttempts` / GAS rows: `config.inbox.inboxMaxRetries`; CW rows: the `maxAttempts` CW returns per row | `completionAttempts` / GAS rows: `config.outbox.outboxMaxRetries`; CW rows: CW's per-row `maxAttempts` |
| `lastFailureAt` | `lastResubmissionDate` | `lastResubmissionDate` |
| `traceId` | `traceparent`, W3C middle segment extracted (`00-<32hex>-…` → the 32-hex trace id; bare values passed through); `null` when absent | `event.traceparent` same treatment; `null` for audit rows |
| `completedAt` | `completionDate` | `completionDate` |

Nothing else from the document is returned — in particular never `event`, `event.data`, `claimedBy`, full ARNs, `audit.entities[].entityid` (an application/agreement reference) or `audit.details`. Only `entity` and `action` are ever projected from audit entities, and they are consumed by the type derivation, not returned.

### Table columns (FE) — per the Claude Design handoff (Event Stream.dc.html)
Column order: **Event ID / Type · Status · Route · Created At · Attempts · Last Failure**.
| Column | Rendering |
|---|---|

| **Status** | `badge` with mono raw text: `PUBLISHED` → `badge-ghost` (queued, healthy); `PROCESSING` → `badge-info`; `FAILED`, `RESUBMITTED` → `badge-warning` + trailing ↻ (retrying); `COMPLETED` → `badge-success`; `DEAD_LETTER` → `badge-error`; anything unrecognised → `badge-ghost`. The view model decides the *role*; the literal daisyUI class lives in the `status-badge` template (Tailwind only scans `views/`) |
| **Route** | Human hop, left-to-right: line 1 bold `GAS → Caseworking` (full names: GAS, Caseworking, Agreements, Audit); line 2 small mono muted `outbox · via cw__sns__update_status_fifo` or `inbox`. Outbox destination derived from the target prefix (`cw__*` → Caseworking, `gas__*` → GAS, `internal` → own service, `audit` → Audit); inbox origin from `source`. No DLQ chip — the status badge carries dead-letter |
| **Created At** | Relative, server-rendered (`22m ago`, `3h 12m ago`, `2d ago`), dotted underline + `cursor: help`; `title` carries the ISO UTC instant and the absolute Europe/London form (`16 Jun 2026, 12:00:00 BST`) |
| **Attempts** | right-aligned mono `3 / 5`; `text-error font-bold` when `attempts >= maxAttempts` |
| **Last Failure** | same relative treatment in `text-error`; plain `-` (no underline) when null |

Row treatments: `COMPLETED` rows recede at 0.55 opacity; `DEAD_LETTER` rows carry a faint error-tinted background. Page header (in-content): `Events` h1 with a subtitle stating the active filter, or "No filter applied — showing all statuses, both services, both boxes." when none.

Pager below the table: **Previous** → `?cursor=<startCursor>&direction=backward`, **Next** → `?cursor=<endCursor>&direction=forward`, each rendered only when its flag is true. Above the table when `sourceErrors` is non-empty: `alert alert-warning` "Some event sources are unavailable: <service · box, …>. Showing the rest." Whole-request failure: `alert alert-error` "Events could not be loaded from GAS." Empty: "No events found."

Footer note under the table: "Data may be a few seconds behind (read from a secondary)."

## Acceptance criteria

**Access**
- Given a signed-in user with `FCP.GrantOperationsAdmin`, when they open `/dev-ops/events`, then the table renders. Given a user without it, then they are refused as other `/dev-ops` routes are.
- Given a request to `GET /grant-admin/events` without a valid service bearer token, then GAS responds `401`.

**Content**
- Given events in all four sources and **no filter parameters**, when the page loads, then rows from all four sources, of every status and kind (including audit), appear ordered by `createdAt` descending with the six columns above — nothing is excluded by default.
- Given `?status=DEAD_LETTER`, then only `DEAD_LETTER` rows from all sources are listed and Previous/Next links carry `status=DEAD_LETTER`.
- Given `?service=gas`, then only GAS inbox/outbox rows are listed and Caseworking is not called.
- Given `?status=BOGUS` or `?service=other`, then the FE forwards them unvalidated, GAS responds `400`, and the events page renders with the error alert (not the shared error page).
- Given an inbox row with `eventTime = 2026-06-16T10:00:00Z`, then Created At shows a server-rendered relative time (e.g. `22m ago`) whose `title` contains both `2026-06-16T10:00:00Z` and `16 Jun 2026, 11:00:00 BST`; a January instant's `title` carries `GMT`.
- Given an outbox CloudEvent row targeting `cw__sns__update_status_fifo`, then Event ID = `event.id`, Type = `case.status.updated` and Route reads `GAS → Caseworking` with `outbox · via cw__sns__update_status_fifo` beneath.
- Given an inbox row with source `CW`, then Route reads `Caseworking → GAS` with `inbox` beneath; source `AS` renders `Agreements → GAS`.
- Given an audit outbox row, then Event ID = its `_id`, Type = `audit · APPLICATION.CREATE` (per its first entity/action) and Route reads `GAS → Audit`.
- Given a row with `completionAttempts = 5` and max 5, then Attempts shows `5 / 5` in red.
- Given a `DEAD_LETTER` row, then the Status badge is red `DEAD_LETTER` and the row carries a faint error tint (no separate DLQ chip); given `PUBLISHED` → ghost, `PROCESSING` → info, `FAILED`/`RESUBMITTED` → warning with ↻, `COMPLETED` → success at 0.55 row opacity.
- Given a row whose status is outside the six known values, then it renders with a ghost badge and the page does not fail.
- Given a row with no failure, then Last Failure shows a plain `-` with no underline or tooltip.
- Given a row whose `segregationRef` is `GLD-9B2-BWS-grasslands`, then it is shown beneath the type.

**Pagination**
- Given more than 20 events across sources, then exactly 20 are shown, `hasNextPage` is true, and Next links to `?cursor=<endCursor>&direction=forward`.
- Given a page reached via Next, then Previous links to `?cursor=<startCursor>&direction=backward` and returns exactly the previous 20 rows in the same order.
- Given a new event written between two requests, then no row is duplicated or skipped across pages.
- Given three sources exhausted and one with more rows, then Next remains available and the next page contains only that source's rows.
- Given a tampered cursor, then GAS responds `400 Cannot decode cursor` and the FE shows the error alert.
- Given the first page, then no Previous link; given the last page, then no Next link.

**Failure states**
- Given CW unreachable, timing out, or not configured, then GAS rows render, the warning alert lists the Caseworking sources, and Previous/Next continue to work for GAS rows.
- Given exactly one GAS source fails, then the other three sources' rows render with the warning alert listing it.
- Given CW returns `401`, then it is treated as unavailable (same alert) and the response body is not logged.
- Given both GAS reads fail, then no rows and the error alert.
- Given no events anywhere, then "No events found" and no pager.

**Layout & scope**
- Given a narrow viewport, then the table scrolls horizontally inside its container; the page body does not.
- Given the page renders, then no Actions or Error column, application filter, status tabs, counts, purge control, source-status chips, or copy-to-clipboard affordance are present, and the page contains no client-side JavaScript beyond the existing shell.
- Given the response payload, then it contains no `event`, `event.data`, `claimedBy`, full ARN values, or any business identifier from a payload (`traceId`, derived from `traceparent` alone, is the one field sourced from inside `event`).
- Given a row with a `traceId` and a configured logs base URL, then the trace link opens OpenSearch in a new tab filtered to that trace id; given no `traceId` or no configured base URL, then no link is rendered.

## Edge cases & error handling
- Identical `createdAt` across sources → tie-break on `service`, `box`, `_id` (deterministic; cursor stable).
- Inbox row without `eventTime` (pre-backfill) or outbox row with a string `publicationDate` → normalised via `new Date()`; invalid → `_id` timestamp.
- Outbox `event` lacking `id`/`type` → derived per table; never a blank cell.
- `lastResubmissionDate` null on a `FAILED` row (claim-expiry sweep) → Last Failure `-`.
- Source recovers mid-navigation → its rows simply appear from the next page; earlier pages aren't retro-fitted.
- `direction` other than `forward|backward`, or an unknown `status`/`service` → `400` from Joi.
- Cursor reused with a different `status`/`service` than it was issued under → accepted (it is only a keyset position); results are simply the filtered stream from that position.
- Cursor `v` unknown → `400 Cannot decode cursor` (format can evolve).
- An audit row with an empty `entities` array → Type `-`; still listed.
- A status value outside the six → passed through as a string; FE ghost badge; never a 500.

## Data / interfaces

### GAS — `GET /grant-admin/events`
Query (Joi): `cursor: string`, `direction: valid('forward','backward').default('forward')`, `status: valid('PUBLISHED','PROCESSING','FAILED','RESUBMITTED','COMPLETED','DEAD_LETTER')` (optional), `service: valid('gas','caseworking')` (optional). No `status`/`service` = All.
Auth: default `service` strategy (as `/grant-admin/…/claims`). `tags: ["api"]`, `response.schema` enforced.

```json
{
  "events": [{
    "service": "gas",
    "box": "outbox",
    "id": "665f1c2e9a1b2c3d4e5f6a7b",
    "eventId": "3f2c1a0e-…",
    "type": "case.status.updated",
    "fullType": "cloud.defra.prd.fg-gas-backend.case.update.status",
    "source": null,
    "target": "cw__sns__update_status_fifo",
    "segregationRef": "GLD-9B2-BWS-grasslands",
    "status": "DEAD_LETTER",
    "attempts": 5,
    "maxAttempts": 5,
    "createdAt": "2026-06-16T10:00:00.000Z",
    "lastFailureAt": "2026-06-16T10:16:05.000Z",
    "completedAt": null,
    "traceId": "4bf92f3577b34da6a3ce929d0e0e4736"
  }],
  "pagination": {
    "startCursor": "eyJ2IjoxLCJnYXNJbmJveCI6…",
    "endCursor": "eyJ2IjoxLCJnYXNJbmJveCI6…",
```

`service ∈ gas|caseworking`, `box ∈ inbox|outbox`; `status` is validated as a string (documented values `PUBLISHED|PROCESSING|FAILED|RESUBMITTED|COMPLETED|DEAD_LETTER`) so a single unexpected document cannot fail the whole page; `fullType` nullable. Timestamps ISO-8601 UTC. There is no `kind` field — audit rows are identified structurally in the mapper.

Files: `src/grant-admin/routes/find-events.route.js`, `use-cases/find-events.use-case.js`, `repositories/cw-actuators.repository.js` (uses `common/wreck.js`, `config.cwBackend`), `schemas/find-events-response.schema.js`; `src/grants/repositories/{inbox,outbox}.repository.js` gain `findPage({ cursor, direction, pageSize })` using `paginate()` with per-source codecs — inbox `eventTime` (ISO string, compared as string), outbox `publicationDate` (Date ↔ ISO) — and `_id` (ObjectId ↔ hex); `migrations/<ts>-add-event-list-indexes.js`.

### CW — consumed here, delivered by FGP-1227
`GET /actuators/inbox` and `GET /actuators/outbox` — query `cursor, direction, pageSize (≤ 50), status (optional; absent = all)`; `auth: "public-api"`; response `{ data: [<row projection>], pagination: { startCursor, endCursor, hasNextPage, hasPreviousPage } }` from `paginate.js`; projection limited to the generic fields in the derivation table plus `auditEntities` (`[{ entity, action }]` only — never `entityid` or `details`) and `maxAttempts` (CW's own `INBOX_MAX_RETRIES`/`OUTBOX_MAX_RETRIES`); `target` is returned as the raw ARN and reduced by GAS. Never `event`, `event.data`, `claimedBy`.

### FE — `fg-grants-platform-admin`
`src/dev-ops/routes/view-events.route.ts` (Joi query `{ cursor?, direction?, status?, service? }` as optional plain strings — the FE does **not** enforce the enums; it forwards and lets GAS's `400` surface as the in-page alert), `use-cases/get-events.use-case.ts`, `repositories/events.repository.ts` (`getFromGas`), `view-models/events-page.view-model.ts` (formatting via `Intl.DateTimeFormat('en-GB', { timeZone: 'Europe/London', …, timeZoneName: 'short' })`; badge *role* mapping and Route/relative-time derivation — class literals live in the templates; pager hrefs preserving other query params), `views/events.njk` extending `layouts/page.njk`; components `status-badge`, `pager` under `views/components/`.

## Non-functional
- Read-only. No payload bodies, claim tokens or business identifiers in any response; nothing from a payload written to logs (`describeError`-style one-liners only).
- Each request reads ≤ `pageSize + 1` documents per source; no `countDocuments`; no full-collection loads.
- CW fan-out in parallel, bounded by the shared 3 s `wreck` timeout, no retries.
- Merged page latency target ≤ 1 s with CW healthy on a warm index.
- New GAS env vars must be **optional** in `config.js` (it `process.exit(1)`s on missing required vars).
- Production GAS reads use `readPreference: secondary` — list may lag by seconds; disclosed in the footer.
